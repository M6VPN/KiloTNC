# TNC1200 Host Harness

This document covers the host-side TNC1200 integration harness. It connects the existing KISS parser, AX.25 framing, AFSK1200 streaming TX, AFSK1200 streaming RX, and M1.8 channel-control simulation modules without hardware dependencies.

## Purpose

TNC1200 proves the portable modules can behave like a simple KISS TNC in deterministic host tests. It is not STM32 firmware, USB CDC device code, a GPIO PTT controller, or a real-radio interface.

## TX Pipeline

```text
KISS byte stream from host
	|
	KISS parser
	|
	KISS data command 0
	|
	raw AX.25 frame bytes with FCS
	|
	AFSK1200 streaming TX
	|
	signed 16-bit PCM chunks
```

`tnc1200_host_input()` accepts arbitrary chunks of KISS bytes. A decoded KISS data frame is stored as one pending AX.25 frame if TX and the pending slot are idle. If TX is busy or a pending frame already exists, the new frame is rejected and counted. There is no multi-frame transmit queue in M1.8.

The pending frame does not emit PCM until the channel-control simulation grants access, PTT is on, and TXDELAY has elapsed.

## RX Pipeline

```text
signed 16-bit PCM chunks
	|
	AFSK1200 streaming RX
	|
	raw AX.25 frame bytes with FCS
	|
	KISS data command 0
	|
	KISS byte stream to host
```

`tnc1200_rx_process()` accepts arbitrary PCM chunks and writes KISS data frames into the caller output buffer. If a decoded RX frame does not fit in the caller buffer, the KISS output is dropped and `rx_frames_dropped` is incremented.

## KISS Commands

| Command | M1.8 behavior                                            |
| ------- | -------------------------------------------------------- |
| 0       | Data frame queues one pending AX.25 frame for TX         |
| 1       | TXDELAY updates PTT delay and TX preamble flag count     |
| 2       | P updates p-persistence channel access                   |
| 3       | SlotTime updates p-persistence retry slot time           |
| 4       | TXtail updates PTT tail and TX trailing flag count       |
| 5       | FullDuplex updates DCD gating behavior                   |
| 6       | SetHardware payload is stored by KISS parser             |
| 255     | Return is a no-op                                        |

Unsupported commands are ignored and counted by the KISS parser.

## M1.8 Channel Control

TNC1200 now uses `tnc_control` for host-side channel access and PTT timing:

- DCD busy blocks TX when FullDuplex is off.
- FullDuplex allows TX even when DCD is busy.
- p-persistence uses a deterministic local PRNG.
- TXDELAY holds simulated PTT on before AFSK TX starts.
- TXTAIL holds simulated PTT on after AFSK TX completes.
- The maximum TX watchdog forces PTT off and clears pending TX state.
- Abort forces PTT off and clears pending TX state.

New host-side APIs expose the simulation:

```text
tnc1200_set_dcd()
tnc1200_ptt_state()
tnc1200_can_emit_audio()
```

No real PTT pin is controlled by TNC1200.

## Stats

The TNC1200 stats include:

- KISS frames in and out.
- KISS parse errors.
- Ignored KISS commands.
- TX frames started, done, and rejected.
- RX frames OK, bad FCS, malformed, and dropped.
- PCM samples in and out.
- Channel access requests, grants, DCD denials, p-persistence deferrals, timeouts, aborts, and PTT transitions.

## Limitations

- Host-side deterministic vectors only.
- Host-side PTT simulation only, no GPIO.
- Host-side DCD flag only, no real squelch or COS input.
- No USB CDC device code.
- No hardware audio path.
- No real-radio testing.
